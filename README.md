# Aero Metrics

## Explainable AI & Automated MLOps Platform for Air-Quality Forecasting

Aero Metrics is an end-to-end machine learning platform for air-quality analysis, prediction and multi-horizon forecasting across India.

The platform combines air-quality and weather data from **46 Indian cities** and processes **200,000+ records** to provide pollution predictions, 48-hour forecasts, multi-city comparisons, historical analytics, what-if simulation and model explainability.

The project was built to go beyond model development by implementing a reproducible ML pipeline, automated retraining, experiment tracking, artifact management, CI/CD and cloud deployment.

## Overview

Air-quality forecasting involves more than predicting a pollutant concentration.

A useful system should be able to:

- Predict current pollution levels
- Forecast future pollution levels
- Compare expected pollution across cities
- Analyse historical pollution and weather patterns
- Explain why a model produced a particular prediction
- Incorporate newly collected data automatically
- Retrain models without manually rebuilding the entire ML workflow
- Track experiments and model performance
- Deploy updated application components reliably

Aero Metrics addresses these requirements through an integrated ML and MLOps architecture.

# Key Features

## 1. Current Pollution Prediction

Predicts **PM2.5 and PM10** using historical pollution, meteorological and temporal features.

The prediction system incorporates:

- Historical pollutant values
- Weather conditions
- Temporal characteristics
- City-specific information
- Engineered lag and rolling features

---

## 2. Multi-Horizon Forecasting

Aero Metrics supports pollution forecasting across multiple future horizons:

- 12 hours
- 24 hours
- 48 hours

The forecasting system uses available future weather information to generate predictions for the selected horizon.

It also provides:

- Automated forecasting mode
- Manual forecasting mode
- Multi-city forecasting
- Single-plot comparison of forecast trajectories

---

## 3. Multi-City Comparison

Users can forecast multiple cities simultaneously and compare their expected pollution trajectories.

This makes it possible to analyse differences in pollution behaviour across locations rather than examining each city independently.

---

## 4. Historical Analytics

The analytics module provides historical exploration of air-quality and weather data.

Users can filter and analyse data by:

- City
- Region
- Season
- Year
- Time of day

The dashboard is designed to expose temporal and geographical patterns in pollution.

---

## 5. What-If Analysis

The simulator allows users to modify environmental inputs and observe how those changes affect model predictions.

This provides a practical way to explore model sensitivity to changing weather conditions.

The feature is intended for **model exploration rather than causal inference**.

---

## 6. Explainable AI

Aero Metrics uses **SHAP** to explain model predictions.

The explainability system provides:

- Global feature importance
- Local prediction explanations
- Feature contribution analysis
- Positive and negative feature contributions
- Individual prediction explanations

The platform also uses **Google Gemini** to convert model and SHAP outputs into natural-language explanations.

The language model is used as an explanation layer; the underlying prediction remains generated by the trained ML model.

### Performance Summary

The current-value predictors achieve cross-validation R² scores of:

- **PM2.5 Predictor:** 0.80
- **PM10 Predictor:** 0.82

For multi-horizon forecasting:

- **PM2.5:** CV R² ranges from **0.837 at T** to **0.568 at T+48h**
- **PM10:** CV R² ranges from **0.787 at T** to **0.607 at T+48h**

R² decreases as the forecasting horizon increases, which is expected as uncertainty accumulates further into the future.

# MLOps & Automation

A major objective of Aero Metrics was to automate the machine learning lifecycle rather than treating model training as a manual notebook workflow.

The overall pipeline is:

```text
Data Collection
      ↓
Data Processing
      ↓
Feature Engineering
      ↓
DVC Pipeline
      ↓
Model Training
      ↓
Evaluation
      ↓
MLflow / DagsHub
      ↓
Azure Blob Storage
      ↓
Docker
      ↓
GitHub Actions
      ↓
Azure Container Apps

```
